# 上岸账本 v4

所有持久化金额使用整数分；输入表单接受人民币元，最多两位小数。日期用 `YYYY-MM-DD`，业务时区为 `Asia/Shanghai`，时间戳使用 ISO 8601。稳定 ID 一旦创建，不因页面排序或升级而变化。

## 账本与账户

| 字段 | 含义 |
| --- | --- |
| `format` / `schemaVersion` | `cn.shore.ledger` / `4` |
| `id` / `revision` | 账本标识与递增修订号 |
| `currency` / `timeZone` | `CNY` / `Asia/Shanghai` |
| `trackingSince` | 开始记录日期，决定能否宣称完整月度变化 |
| `mode` | `personal` 或 `demo` |
| `budget` | 月度自有还款预算、收入/生活/备用预算、已到账自有现金；收入预算不增加现金 |
| `accounts` | 平台与亲友借款，包括已结清记录 |
| `events` | 追加流水，带操作标识、本金变化、资金来源、息费及撤销快照 |
| `baselines` | 用户核对的月初总本金及当时覆盖的账户 ID |
| `plans` | 试算输入、状态、修订号，与实际流水分开 |
| `extensions` | 扩展与旧版完整原始数据 |

账户保存 `principalCents`、`openingPrincipalCents`、`availableCents`、`trackingFrom`、`balanceAsOf`、`entryType`、`kind`、`bills` 与修订号。`availableCents` 是尚未使用的借入资金，不能再次作为新增借款计入。`entryType=existing` 的建档不会增加当月新增本金；`new` 则计入新增本金。

账单保存稳定 `id`、`dueDate`、`amountCents`、可空的 `principalCents`、`principalSource`、`paidCents`、可空的 `paidPrincipalCents`、`voidedCents`。来源为 `actual`、`estimated` 或 `unknown`。应付余额为金额减已还和已作废部分。平台明确报价结清时才可作废剩余应付账单；预测不擅自假定免息。

## 本金变化与预计

实际还款的本金减少由平台还后余额核对；只有各期真实本金完整且整期支付时可自动确定。未知流水本金用 `null`，不能当成零或息费。月度变化优先使用用户核对的月初余额；否则仅记录可确定的变化，未覆盖整月时显示「建账以来」。界面月度汇总使用当前业务日期，不把当前余额充当历史月末余额。

预测现金流以剩余实际账单为基础；未知的未来各期本金按剩余本金比例分配，并标记预计，不回写实际本金。月度自有预算扣除当月已用资金，包含全部亲友债。存在缺口、未覆盖本金或超过预测范围时，不给出可实现的还清日期。

借贷还款将新借款和目标还款保存为一个 `refinance` 事件。本金净变化是新增本金减归还本金。方案输入单独保存，不改变实际现金、债务和流水。操作标识防重复；撤销追加 `reversal` 事件，并保留原记录。撤销后的方案可以再次执行，但新的执行同样防重复。

## 备份文件

```json
{
  "format": "cn.shore.backup",
  "backupVersion": 1,
  "schemaVersion": 4,
  "exportedAt": "ISO 8601",
  "ledgerId": "账本 ID",
  "checksum": { "algorithm": "sha256", "value": "64 位十六进制" },
  "data": { "完整账本": "原字段保留" }
}
```

校验输入是 `data` 的规范 JSON：对象键按字符排序，数组顺序保留，UTF-8 编码。SHA-256 用于检测损坏，不提供加密或来源认证。备份包含原始迁移数据，应按个人财务文件保管。最大 32 MiB UTF-8。

导入保留未知字段，拒绝无效金额、日期、重复标识、损坏校验和及未来版本。同一账本的同一版本可重复导入而不重复计账；仅接受事件完全一致且修订顺序可验证的扩展。遇到分叉拒绝自动合并，保留两份供用户核对。整本恢复须确认，恢复前的当前版本进入本地快照。

## v3 迁移与后续升级约束

迁移保留账户、亲友债、已结清记录、资金余额、现金和历史流水。原始输入完整保存于 `extensions.legacyV3.original`，SQLite 同时保存原文，原 SharedPreferences 不删除。相同 v3 输入产生确定的迁移账本 ID。旧模型生成的未来账单标记为 `estimated`，不能冒充平台实际账单。

SQLite 以事务保存完整快照，UTF-8 字节按 64 KiB 分块，避免 CursorWindow 单行限制。仅在新快照及分块全部写入后提交；保留最近 20 次保存和独立的旧版原文。读取损坏数据时禁止自动初始化空账本。持久化失败时保留原内存状态和输入草稿；提交结果不确定时先读回确认，避免重复操作。

后续版本必须通过显式迁移链升级，先验证并保留原始备份，再写新格式；不能删除旧 ID、原流水或未知字段。高版本备份只能交由支持它的版本读取，不能降级覆盖。包名和签名必须保持兼容，测试须覆盖 v3 → v4 → 导出 → 恢复的往返。
